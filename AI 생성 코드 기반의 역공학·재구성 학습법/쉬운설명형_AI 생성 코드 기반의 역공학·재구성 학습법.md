
**실습 예제: YOLO 배추김치 이물질 검출 프로젝트**

**학습 목표:** AI가 작성해 준 코드를 단순히 실행하는 것이 아니라, 스스로 요구사항을 정의하고, 
코드의 역할을 이해하고, 오류를 검증하고, 개선할 수 있는 능력을 기릅니다.

### 1. 내가 만들고 싶은 기능을 한글로 작성합니다

생성형 AI에게 곧바로 코드를 작성해 달라고 하지 않습니다.

먼저 무엇을 만들고 싶은지, 어떤 입력을 사용하고 어떤 결과를 얻을 것인지 직접 생각합니다.

예를 들어 YOLO를 학습시키기 전에 다음 과정을 먼저 확인하고 싶다고 가정합니다.

1. Data Audit으로 데이터 점검
2. YOLO Dataset 구성
3. 작은 Smoke Test 실행
    
이때 단순히 작업 이름만 나열하지 않고, 어떤 조건을 만족하면 성공한 것인지도 작성합니다.

### 2. 한글로 코딩하듯이 최소 뼈대를 작성합니다

Python 문법을 완벽하게 알고 있지 않아도 괜찮습니다.

예를 들어 다음처럼 작성합니다.

- 이미지 폴더를 읽는다.
- 이미지 파일이 정상적인지 확인한다.
- 이미지와 라벨 파일이 서로 연결되는지 검사한다.
- 라벨의 클래스와 BBox 좌표를 검사한다.
- 오류가 발생하면 기록하고 필요한 경우 실행을 중지한다.
- 정상 데이터로 YOLO 데이터셋을 구성한다.
- 사전학습된 YOLO 모델을 불러온다.
- 소량의 데이터로 짧게 학습한다.
- 실행 결과와 로그를 저장한다.
    
이것을 **한글 의사코드(Pseudocode)**라고 합니다.

### 3. 생성형 AI에게 첫 번째 설계 검토를 요청합니다

**프롬프트 예시 ①**

"YOLO 딥러닝을 이용하여 배추김치 이물질 검출 모델을 개발하려고 합니다.

우선 다음 세 가지 과정을 진행하고 싶습니다.

1. Data Audit
2. YOLO Dataset 구성
3. 작은 Smoke Test
    

이 과정을 구현하기 위한 최소한의 뼈대 코드를 한글 의사코드로 작성해 주세요.

각 단계에서 필요한 입력, 처리 과정, 출력, 발생 가능한 오류를 설명해 주세요.

지금은 Python 코드를 작성하지 말고 실제로 코딩하는 것처럼 한글로 순서를 작성해 주세요."

### 4. AI가 작성한 한글 코드를 읽고 직접 세분화합니다

첫 번째 답변을 그대로 확정하지 않습니다.

내가 이해하지 못한 부분, 누락된 조건, 더 상세히 알고 싶은 부분을 찾아봅니다.

**프롬프트 예시 ②**

"앞서 작성한 한글 의사코드를 더 세분화하고 싶습니다.

Data Audit 단계에서는 이미지 손상 여부, 이미지와 라벨의 대응 관계, 클래스 번호, BBox 좌표 오류를 검사하도록 해 주세요.

정상 이미지에 이물질이 없어 라벨이 비어 있는 경우는 오류로 처리하지 않도록 구분해 주세요.

그리고 각 단계에서 왜 이러한 검사가 필요한지 쉽게 설명해 주세요."

이처럼 한 번에 모든 코드를 요청하지 않고, 자신의 생각을 발전시키면서 설계를 구체화합니다.

### 5. 완성한 한글 설계를 Python 한 파일로 구현합니다

한글 의사코드의 전체 흐름을 이해했다면 생성형 AI에게 Python 코드를 요청합니다.

이 단계에서는 기능을 여러 파일로 나누지 않고 **최소 실행 가능한 단일 파일**로 작성합니다.

단, 학습 목적은 전체 시스템을 한 파일에 무조건 넣는 것이 아닙니다.

이번에 설계한 Data Audit, Dataset 구성, Smoke Test만 포함합니다.

함수 단위로 나누어 어떤 코드가 어떤 역할을 수행하는지 확인합니다.

### 6. 터미널에서 작은 Smoke Test를 실행합니다

작성한 Python 파일을 실제로 실행합니다.

전체 데이터를 오랫동안 학습시키는 것이 아니라 적은 데이터와 짧은 학습 시간으로 실행 흐름이 정상적인지 확인합니다.

이 단계에서 확인할 내용은 다음과 같습니다.

- 이미지와 라벨을 정상적으로 읽는가?
- 데이터셋 설정이 올바른가?
- 모델을 정상적으로 불러오는가?
- 짧은 학습이 오류 없이 시작되고 종료되는가?
- 결과와 로그가 저장되는가?
    
**Smoke Test 통과는 모델 성능이 좋다는 의미가 아닙니다.**

### 7. 한 파일에 작성된 코드를 기능별로 분리할 방법을 생각합니다

우선 코드를 다음 네 개의 기능 영역으로 구분합니다.

1. 입력
2. 전처리
3. 핵심 로직 처리
4. 출력
    
그리고 모든 기능에 대해 별도로 검증을 수행합니다.

예를 들어 최종 YOLO 추론 프로그램에서는 다음처럼 기능을 분리할 수 있습니다.

|기능|파일 예시|주요 역할|
|---|---|---|
|입력|`image_input.py`|이미지 읽기 및 검사|
|전처리|`preprocessing.py`|필요한 이미지 변환|
|YOLO 추론|`detector.py`|모델 로드 및 예측|
|후처리·판정|`postprocessing.py`|Confidence, 클래스, 판정 처리|
|출력|`output.py`|BBox 표시, 결과 저장|

파일 개수를 반드시 다섯 개로 맞출 필요는 없습니다.

초기 Smoke Test에서는 `audit.py`, `dataset.py`, `train_smoke.py`처럼 해당 단계에 필요한 기능부터 분리합니다.

YOLO 라이브러리가 이미 처리하는 정규화나 NMS 등의 기능을 불필요하게 중복 작성하지 않도록 주의합니다.

### 8. 생성형 AI보다 먼저 내가 직접 코드를 분리해 봅니다

기존 한 파일의 코드를 살펴보고 기능에 따라 나눠 봅니다.

틀려도 괜찮습니다.

각 함수가 어떤 입력을 받고 무엇을 반환하는지 확인하며 파일을 옮겨 봅니다.

분리한 파일을 연결할 때 문제가 발생하면 전체 코드를 다시 작성해 달라고 하지 않습니다.

막히는 함수나 import 부분을 먼저 스스로 살펴본 후 해당 부분만 AI에게 질문합니다.

### 9. 파일별 단위 테스트를 작성합니다

이제 각 함수가 의도한 대로 동작하는지 자동으로 검증합니다.

**입력 모듈**

- 이미지가 정상적으로 열리는가?
    
- 존재하지 않는 파일 경로를 처리하는가?
    
- 손상된 이미지를 처리하는가?
    

**전처리 모듈**

- 이미지 크기와 채널이 예상한 값인가?
    
- 자료형이 올바른가?
    
- 불필요한 중복 변환이 없는가?
    

**YOLO 추론 모듈**

- 모델 호출에 필요한 인자가 전달되는가?
    
- 검출 결과를 정상적으로 반환하는가?
    
- 모델 호출 실패를 처리하는가?
    

**후처리·판정 모듈**

- Confidence 임계값이 정상적으로 적용되는가?
    
- 이물질 클래스가 올바르게 처리되는가?
    
- 검출 결과가 없거나 여러 개인 경우에도 작동하는가?
    

**출력 모듈**

- 결과 파일을 지정된 위치에 저장하는가?
    
- 저장된 결과 내용이 올바른가?
    
- 저장 실패를 처리하는가?
    

이 단계에서는 `pytest`를 사용할 수 있습니다. 실제 모델 실행 없이 검증할 수 있는 부분에는 가상의 입력값이나 Mock 객체를 활용합니다.

### 10. 분리한 파일을 연결하여 통합 테스트합니다

개별 모듈이 정상적으로 동작하더라도 모듈을 연결하면 오류가 생길 수 있습니다.

각 함수의 반환값이 다음 함수의 입력값과 맞는지 확인합니다.

모듈을 분리한 후에는 앞서 진행한 작은 Smoke Test를 다시 실행합니다.

코드가 변경될 때마다 기존 테스트를 반복하여 이전 기능이 손상되지 않았는지도 확인합니다.

### 11. 터미널에서 디버깅하고 해결 기록을 남깁니다

오류가 발생했다면 곧바로 전체 코드를 다시 생성하지 않습니다.

오류 메시지를 읽고 원인을 추측해 봅니다.

해결되지 않으면 AI에게 관련 코드와 오류 메시지를 전달하여 피드백을 받습니다.

**디버깅 기록은 다음 형식을 사용합니다.**

- 발생한 문제
    
- 실행한 명령어
    
- 오류 메시지
    
- 내가 생각한 원인
    
- 실제 원인과 수정한 코드
    
- 수정 후 테스트 결과
    

해결된 오류는 가능하면 자동 테스트에 추가하여 다시 발생하는지 확인할 수 있도록 합니다.

### 12. 코드 최적화 이전에 스스로 문제점을 찾아봅니다

정상적으로 작동하는 코드를 먼저 보존합니다.

이후 다음 내용을 스스로 확인합니다.

- 중복된 코드가 있는가?
    
- 사용하지 않는 함수나 변수가 있는가?
    
- 너무 긴 함수가 있는가?
    
- 한 함수가 너무 많은 역할을 담당하고 있는가?
    
- 같은 데이터를 불필요하게 반복해서 읽는가?
    
- YOLO 모델을 매번 다시 불러오는 코드가 있는가?
    
- 불필요한 계산이나 파일 저장이 있는가?
    

코드 정리와 성능 최적화는 구분해야 합니다.

실행시간과 메모리 사용량을 측정하여 실제로 개선할 필요가 있는 부분을 확인합니다.

### 13. 생성형 AI에게 코드 리뷰와 최적화를 요청합니다

**프롬프트 예시 ③**

"현재 코드는 단위 테스트와 통합 테스트를 통과했습니다.

이제 코드 품질과 성능을 개선하고 싶습니다.

중복 코드, 불필요한 함수, 반복 연산, 비효율적인 파일 처리, 함수의 역할 분리가 적절하지 않은 부분을 검토해 주세요.

먼저 어떤 코드가 왜 문제인지 설명하고, 수정했을 때 얻을 수 있는 효과와 위험을 알려 주세요.

기존 입력·출력과 판정 로직은 변경하지 말고 필요한 부분만 수정해 주세요.

또한 성능 개선 여부를 실제로 측정할 수 있는 방법을 제안해 주세요."

AI가 수정한 코드를 그대로 적용하기보다 원본과 비교하며 변경 이유를 이해합니다.

### 14. 최적화 이전과 이후를 비교합니다

최적화 전후의 코드를 같은 환경과 같은 입력으로 테스트합니다.

|비교 항목|확인 내용|
|---|---|
|기능 정확성|같은 입력에 대해 동일한 결과가 나오는가?|
|자동 테스트|기존 테스트가 모두 통과하는가?|
|실행시간|실제 처리속도가 개선되었는가?|
|메모리|메모리 사용량이 감소했는가?|
|코드 품질|중복과 복잡도가 줄어들었는가?|
|유지보수성|기능 수정과 오류 분석이 쉬워졌는가?|

최적화했다고 반드시 속도가 빨라지는 것은 아닙니다.

코드가 더 간결해지더라도 실제 성능 차이가 없을 수 있습니다.

따라서 **개선되었다고 주장하기 전에 테스트 결과와 측정값으로 확인합니다.**

코드를 처음부터 모두 직접 작성하지 못하더라도 괜찮습니다. 중요한 것은 AI가 작성한 코드를 읽고, 구조를 이해하고, 스스로 변경하고, 올바른 동작을 검증할 수 있도록 반복 연습하는 것입니다.
